## 结论

- 页面标题为“热门榜”。标签明确为“全站TOP50”（sub_rank_type=1）和“新人”（sub_rank_type=2）。
- 接口 GET /xlive/general-interface/v1/rank/getHotRankV3。官方请求参数为 ruid、room_id、platform、sub_rank_type。
- 全站热门榜请求实例：https://api.live.bilibili.com/xlive/general-interface/v1/rank/getHotRankV3?ruid=3632305195190283&room_id=1837229404&platform=web&sub_rank_type=1
- 一次返回 list 的 50 个位置（本次 rank 1—50）；官方页面不传 page 或 page_size。不能把 getHotRankList 的人气榜 100 条当成这一榜单。
- list[].room_id 是实际房间号；rank 是榜位；score 是热门值。uinfo.uid / uinfo.base.name 是公开主播身份，area_id / parent_area_id 是分区。live_status=1 表示直播中；0或其他值不作为当前直播候选。
- last_top 是上时段前三，current_room 是上下文主播位置；二者不混入当前 TOP50。
- interval_time 本次为 15，官方页面以该秒数再取榜；countdown 为结榜剩余秒。没有服务端快照 ID、固定版本字段或分页。扫描器可沿用更低频既有发现节奏。
- ruid 必须为正值：省略或0均返回 HTTP200/code=-400；room_id=0可以成功。用公开主播 uid 作上下文，无需实际登录身份。实测 ruid=1&room_id=1 也匿名成功并返回相同全站榜；生产实现应复用列表中的真实公开 uid/roomid，避免依赖无意义常量。
- 接口仅提供排行榜，不证明电池红包或参与资格。名单候选仍需正常红包扫描与特殊资格过滤。

## 失败处理建议

- 限制请求超时，检查 HTTP 状态、JSON code 与 list 数组结构；412/429/业务风控按现有发现请求处理。
- 失败时保留原始成功时间的已有榜单证据，不能刷新时间；超过证据有效窗口自然退出优先池。
- 不把 getHotRankList 或分区 online 列表作为“成功全站 TOP50”的替代。
- 存储所需小字段即可；room_link 含冗长播放参数，不需保存。
