## 二、你问的"另外两个接口"

### 1. `getLotteryInfoWeb` — 拿不到（-352）

```
GET https://api.live.bilibili.com/xlive/lottery-interface/v1/lottery/getLotteryInfoWeb?roomid=27784229
→ {"code":-352,"message":"-352","ttl":1}
```

我把所有可能的原因都排除了一遍：

| 尝试 | 结果 |
|---|---|
| 住宅直连 | -352 |
| 香港机房节点 | -352 |
| 完整浏览器头（origin/accept/sec-fetch-*） | -352 |
| 加 `need_guard=true` | -352 |
| 换 4 个不同房间 | 全部 -352 |
| **正确 WBI 签名**（w_rid + wts，mixinKey 已验证） | **仍然 -352** |

结论：**这个接口已经不对匿名开放了**。`-352` 是 B 站通用风控码，
不是"未登录"（未登录是 `-101`）。B 站直播页前端自己也不再调它，
改用了 `RedPocketGetInfo`（人气红包）+ `Anchor/Check`（天选）两个独立接口。

> 这也解释了为什么那个抢包脚本（gf_602781.js）里虽然写着 `getLotteryInfoWeb`，
> 但代码注释明确说"没有抽奖时部分情况下会返回非 0 code，这里当作无抽奖处理"——
> 作者也踩过这个坑，做了降级处理。

### 2. `RedPocketActiveList` — 拿不到（-101，需登录）

```
GET .../popularityRedPocket/RedPocketActiveList?room_id=27784229
→ {"code":-101,"message":"账号未登录","ttl":1}
```

参数怎么换都是 -101（`room_id` / `roomid` / 加 `platform` / 加 `web_location` / 无参数），
说明**卡的是登录态，不是参数**。

它的价值很高——它一次能返回房间内**所有**进行中的红包（官方 H5 主接口），
比 `RedPocketGetInfo` 更适合批量。

> ⚠️ 订正：我此前写"但代价是必须带 `SESSDATA` Cookie"，这是推断。
> 准确说法是：**匿名一律 -101，带上有效登录 Cookie 后是否可用，我没有账号无法实测**。

## 三、这两类"拿不到"的性质完全不同

```
-101  →  明确表示"未登录"。按惯例带登录态可用，但未实测（能力问题，很可能可解）
-352  →  风控/接口下线。带登录态也未必能用（政策问题，难解）
```

所以：

- **`RedPocketActiveList` / `RedPocketHistory` / `RedPocketGetWinners` / `Anchor/AwardRecord`**
  属于 `-101` 族。**匿名确定拿不到**；登录后能否用属于合理推测，**未验证**。
- **`getLotteryInfoWeb` / `getLotteryInfo`** 属于 `-352` 族。**建议直接放弃**，
  用 `RedPocketGetInfo` + `Anchor/Check` 替代，效果等价。

## 四、这反过来解释了那个站点的"中奖榜"

站点页面上有「中奖榜」（累计电池/单次最大/次数），但：

- `RedPocketGetWinners` → `-101`（匿名拿不到）
- `Anchor/AwardRecord` → `-101`（匿名拿不到）

⚠️ **以下为推断，未经证实**（2026-10-30 19:12 订正）：

我此前写"站点必然持有登录态 B 站账号"，这是**推断当结论，属于过度推断**。
实际能确认的只有"这两个接口匿名返回 -101"。至于站点中奖榜的数据来源，有三种可能，
我没有证据区分：

1. 它确实有登录态账号，调 `RedPocketGetWinners` / `AwardRecord`
2. 它靠自己的用户体系上报（用户授权/手动填）
3. 数据是部分估算或编造的

> 要区分这几种，需要看站点是否提供登录入口、榜单是否包含站点用户之外的人、
> 榜单数值是否与官方可查记录吻合——这些我都没做。

## 五、给你的实用建议

### 想拿红包信息（不改代码）

继续用 `RedPocketGetInfo` + `Anchor/Check`，这两个匿名够用，
配合你 Clash 的 12 个节点轮换，已经验证可跑（1642 房间 / 0 风控）。

### 想用 `RedPocketActiveList`（效率更高）

**推测**需要登录态 Cookie——注意这只是推测，我没有登录账号验证过。
若你要试，风险提示：

- 用**小号**，别用主号
- Cookie 泄露 = 账号被盗，别贴到任何在线工具里
- 该接口即使可用，高频调用同样会触发 `-352`/`412`
- 自动化调用违反 B 站用户协议

### 绝对不要碰

`Anchor/Join` 和 `RedPocketDraw` 是**参与接口**（会真的花电池/发弹幕）。
批量自动参与 = 明确的协议违规 + 账号风险，这不是"抓数据"而是"作弊"。
