## 使用方法

在本地运行 `node deploy/instabox/build-bundle.js` 生成 `bundle/`，上传整个生成目录到机器的 `/data/hongbao`。再在机器运行：

```bash
bash /data/hongbao/deploy/install-runtime.sh
bash /data/hongbao/deploy/install-services.sh
```

代码中的 Windows curl 路径和 Windows 控制器探测被替换，代理、策略组与控制器凭据从专用环境配置读取。桌面通知明确关闭。看板仍只监听 127.0.0.1，优先通过官方 SSH 隧道访问：

```bash
instabox port-forward hongbao-scanner 8443
```

在本机打开 `http://127.0.0.1:8443/pool`，设置保存仍经过原有本地 Host/Origin 检查。不发布公网控制器端口，也不需要修改看板写入鉴权。

## 节点自动维护（2026-11-12）

`manage-node-health.js` 管理云机内已授权的 SS / VMess 候选，最多保存 24 个，扫描组选择 3～8 个不同健康出口。2026-11-12 先追加原扫描分组剩余四个候选（3 个 VMess、1 个 SS），随后为达到八出口，又从同一份保存配置的其他分组筛出四个 SS 候选。当前保存十六个候选；导入候选不代表已通过出口认证。

完整维护先停扫描，再用系统 DNS 和两处独立 DoH 查询节点域名；间隔 12 秒采样两次，只保留同一节点端口两次 TCP 均可达的公网地址。独立临时 Mihomo 进程对每个候选连续执行三轮出口 IP 与真实红包接口查询，网络失败只重试一次，可尝试同一节点已验证的一个备用地址，风控不重试。通过三轮、出口稳定且不同的节点按成功率排序，选取三至八个加入扫描组。通过率不足时保留原配置并停止扫描，启动预检仍要求全部选中节点可查询且至少三个不同出口。

`authorized-nodes.js` 分开限制候选数量（24）和扫描出口数量（8），校验节点协议、凭据存在性、唯一名称和端口；`append-authorized-nodes.js` 接收 stdin 中一至十二个已授权的追加候选，不覆盖原节点或直接加入扫描组。追加前停止扫描与维护，先用 Mihomo 校验临时配置，再原子替换候选配置并保存扩容前备份。固定入口保留 VMess UUID、WebSocket Host / path 及原有 TLS 参数；TLS 未配置 servername 时，在改用 IP 前补留原始域名用于 SNI。原请求预算、并发及重用间隔不变。本轮扩容前十二候选、五出口配置与代码的备份位于云机私有的 `proxy/eight-exits-backup-20261112/`；前一轮备份保留。

`node-dns.js` 在直连解析没有公网 IPv4 答案时，经现有代理交叉查询两处 DoH，并保留来源标记。`screen-saved-candidates.js` 仅传输端点元数据，分别筛查同一保存配置中其他分组的三十四个候选及其本机 DNS 答案，不传输密码。筛查结果私有保存；完整维护只接受十分钟内、原域名/端口/协议均一致且已两次 TCP 连通的提示，随后仍重新验证两轮 TCP 和三轮真实接口。通过完整认证的入口继续保存在健康账本中供后续维护使用。

选中节点按节点固定已验证入口地址，原域名、冷却及验证证据留在云机私有账本中；后续重新解析可更新入口，共用域名但端口不同的节点不会互相覆盖。只有实际验证地址的独立 DNS 才进入 `proxy-server-nameserver`。失败节点冷却 10 分钟、风控 15 分钟，并尊重扫描器已有风控截止时间。配置修改前保存原始和上一份备份，校验或代理重启失败会回退。临时进程和文件正常结束时清理，公共输出只有节点编号和统计。

健康检查计时器每 30 分钟触发；最近半小时每个选中节点至少 20 次查询、成功率达到 90%、最后成功请求仍近期，且完整检测未满一小时、配置指纹一致时，仅更新运行统计。否则暂停扫描并进行完整维护。扫描器启动失败也触发维护。完整维护会产生采集空档；诊断请求计数单独保存，并在生产查询与诊断之间、诊断与恢复扫描之间保留至少 180 秒间隔，现有扫描轮预算与重用间隔未提高。

云端服务通过 `SCANNER_IP_NETWORK_RETRY=1` 为正常扫描的出口 IP 检测启用一次网络失败重试。重试经过原请求节流与计数，包含在每节点每轮 110 次预算内；两次都失败便放弃该轮，HTTP、业务错误和风控不重试。此选项未设置时默认关闭。

```bash
/data/hongbao/runtime/node/bin/node --env-file=/data/hongbao/scanner.env /data/hongbao/deploy/manage-node-health.js
sudo systemctl enable --now hongbao-node-health.timer
```

私有结果：`/data/hongbao/proxy/node-health-ledger.json`；脱敏结果：`/data/hongbao/proxy/node-health-summary.json`。完整维护在应用配置前保存入口采样和实际探测时间，应用出错时仍保留冷却依据。`inspect-status.js` 会返回最新健康汇总和 SQLite 中的实际扫描计数。公共部署清单不包含节点域名、入口地址、密码或账本。

2026-11-12 15:04 的完整维护有九个节点连续通过三轮真实接口检测，已按实际出口去重选择八个，另一个作为备用；扫描已恢复。15:13:58 的实际扫描窗口已验证全部八个不同出口均有成功查询，完成 977 次红包查询，其中 948 次成功，无风控和存储错误。最终生产验证见 `docs/instabox-deploy-20261111/八节点扩容验证-20261112.md`。14:55 再查平台 API 时，机器的 `maxRunMinutes` 已变为 240，当前仍运行；此值由平台动态管理。

扫描提速使用两项调度调整：完整扫描结束且另有满足冷却和重用规则的出口时，轮间等待降至 250 毫秒；无可用出口、空房间池和出错时仍等待 8 秒。慢节点依据最近请求平均耗时，按 30 秒目标缩小下一轮批次，范围为 20～110 次总请求，规划时同步缩放探索和天选配额。五并发、90 毫秒请求启动间隔、每 IP 每轮最多 110 次、180 秒重用间隔和 15 分钟风控冷却不变。近期延迟保存在状态中；旧状态首次启动从历史库最近 30 分钟的最多 110 条请求学习，不产生额外探测。30 秒是批次估算目标，已经发出的请求仍完整处理和落库。

`deploy/inspect-speed.js` 只读历史库，默认统计最近完整十分钟的成功查询吞吐、延迟分位数、轮间空档和各编号节点的表现，支持 `--from`、`--to`、`--run` 固定对比窗口。节点名称、地址和凭据不会输出。

健康选择先要求连续三轮真实接口成功、无风控及不同实际出口，再按每次成功查询的估算耗时排序。若同一出口有维护前五分钟内的至少 20 条实际生产请求，使用平均请求耗时除以成功率；否则使用三轮检测总耗时除以有效响应数，因此网络重试也计入成本。现有节点仅获得 15% 的保留余量，明显更快的已验证备用节点可以替换慢节点，速度接近时保持原组。生产性能只在实际出口与此次检测出口相符时参与比较，地址不会进入公开报告。手工执行 `manage-node-health.js --require-eight` 时，少于八个连续验证的不同出口就不应用替换；定时维护仍保留原有至少三个安全出口的启动规则。

Windows 本地启动器使用 Instabox 0.8.258，启动 `keep-cloud-link.ps1` 后台保活：每十五秒读取一次看板状态，两次连接失败后重建本次扫描器的 SSH 隧道。此过程不调用红包接口，也不恢复暂停的云机器。启动器通过进程记录复用后台连接；电脑重启后仍需双击 `3-查看云端数据.bat`。本机端口被其他程序占用时不会终止那个程序。

## 策略优化顺序

1. 基线迁移先解决持续更新中断，并分开记录平台暂停、程序异常、代理故障与 API 错误。停机不是成功空扫。
2. 分区探索按每个分区统计去重后的新活跃房间数、首次验证的电池来源数与达标来源数。保持每批现有请求上限，重点分区的第二个请求在浅页与第 6–20 页之间分配；小分区遇到空页便回到浅页。不能简单把所有分区的最大页数从 5 改成 20，那会拉长已有浅页重访周期。
3. 将“有资格复查”与“实际多久复查”分开统计。有限预算下先保证普通探索与 WARM 下限，再根据近期独立达标红包证据安排有限的重点来源。报告 p50/p90 实际间隔、开包到首次发现的延迟和首次发现时的剩余秒数。
4. 新开播及新发现房间先给一次验证机会，后续空扫退避；过期 QQ 报告与历史来源不伪装成新开包。跨房间礼物广播仅用于房间发现线索，现有研究不能证明匿名 WebSocket 提供红包开始事件。
5. 基线与优化须在相同时段比较每千次成功查询发现的独立达标红包、房间覆盖和延迟；不以看板当前红包数量或一次短观察直接宣称召回率提升。

目前仍不能证实竞品的完整房间数据库、后台调度、未标记来源的传输方式、出口和账户数量，也不能据网站收益榜断言盈利可信。已测得深页确有额外电池来源，能够指导优化，但不证明竞品采用相同实现。
